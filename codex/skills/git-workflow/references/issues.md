# Issue Workflow

1. Detect the repository and read its Issue conventions.
2. Search open Issues for duplicates using title/body keywords.
3. Draft only relevant sections: summary, reproduction/background, expected result, acceptance criteria, and verification.
4. List existing labels and select only applicable ones.
5. Present title, body, and labels. Create the Issue only after user confirmation.
6. Report the URL and stop. Do not start implementation, add to a Project, or create a branch unless separately requested.

For triage, read current evidence before changing labels or state. Inspection never authorizes external mutation.
