# Dig

プラン・設計・意思決定のあらゆる側面について、共通の理解に達するまでユーザーに徹底的に質問する。

## 進め方

- 質問は必ず一度に一つだけ行う。
- 各質問の前に、コードベースの関連箇所を調べる。
- 調べれば分かることはユーザーに聞かない。
- 甘い回答や曖昧な返答には突っ込む。
- 設計ツリーの各分岐をたどり、判断の依存関係を一つずつ解決する。
- 幅より深さを優先する。
- 新たな洞察が得られなくなるまで一つのテーマを掘り下げてから、次のテーマへ進む。
- 各質問には推奨回答も提示する。
- 論点を掘り尽くしたら終了を提案する。
- ユーザーが続行を求めたら、次に最もリスクが高い未解決テーマを選んで続ける。

## 質問フォーマット

```markdown
### Q[番号]: [質問文]

[なぜこの質問が重要か]

- **A** — [選択肢]
- **B** — [選択肢]
- ...

**推奨: [A/B/...]** — [理由]
```

## 終了時のまとめフォーマット

```markdown
## まとめ

### 決まったこと
- ...
```
